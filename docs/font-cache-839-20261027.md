The earlier Windows combination check reported an UNKNOWN font-open error on a
cold cache and passed after warming. That observation alone did not prove its
cause. An isolated reproduction using the original ensureFont function from
exact PR52 then established three actual defects: two simultaneous cold calls
performed two downloads; a second caller received the final path while only
16 of 32 synthetic fixture bytes were written; an existing non-font file was
treated as a valid cache without repair. The old-source repro produced three
RED assertions (exit 1), preserved in the original A3 #839 task evidence.

Both poster composition and video overlays now import the same font loader.
A process shares its in-flight promise, validates SFNT directory/table bounds,
writes a uniquely named temporary file and publishes only the completed file
by rename. A competing complete cache can be reused if replacement fails on
Windows. Failed downloads or writes release the promise and clean their own
temporary file, so a later invocation may recover. The cache uses the platform
temporary directory; this remains /tmp on the Linux production target and
avoids treating /tmp as a fixed drive-root path on Windows.

This is an integrity guard for the existing trusted Google Noto font download,
not a general font sanitizer or distributed download lock. Separate processes
may download concurrently on a shared cache miss; their published files remain
complete. The font URL, model/provider choice, image-call count, exact copy,
layout/version rules, database, billing, project scope and advertising behavior
are unchanged. Existing complete Linux font caches remain reusable.
